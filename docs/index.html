    Orientação a Objetos
    
Onde cada conceito aparece no código

    
Os requisitos de OOP da disciplina e o trecho do projeto que mostra cada um.

    

      

        
Herança e classe abstrata

        

          
Person tem o método puro exibirInfo() = 0, então não dá para criar uma Person direto. Student e Teacher herdam dela.

class Student : public Person { ... };
virtual void exibirInfo() const = 0;  // em Person
        

      

      

        
Polimorfismo

        

          
calculateStatus() é virtual: FinalExamEnrollment troca a regra de aprovação. No menu, o mesmo ponteiro Person* mostra a ficha certa de aluno ou de professor.

Person* p = aluno;
p->exibirInfo();          // roda Student::exibirInfo()
e->calculateStatus();     // regra normal ou com prova final
        

      

      

        
Encapsulamento

        
CPF, notas e frequência são private. Só dá para mexer neles por getters e setters, que validam o valor. Por exemplo, addGrade() recusa nota fora de 0 a 10.

      

      

        
Ponteiros e referências

        

          
A turma guarda as matrículas como ponteiros. Os métodos recebem objetos por referência, sem copiar.

vector<Enrollment*> enrollments;
bool enroll(Student& s);
        

      

      

        
Singleton e Factory (bônus)

        

          
Database tem construtor privado e uma única instância. PersonFactory cria um aluno ou um professor a partir de um texto.

Database& db = Database::getInstance();
Person* p = PersonFactory::criar("aluno", ...);

    Regras de negócio
    
Como a situação é calculada

    
Enquanto a turma está aberta, o aluno aparece como “Cursando”. Quando o professor encerra, vale a regra da disciplina.

    

      
✔ Sem prova finalFrequência abaixo de 75% reprova por falta. Média 7 ou mais aprova.

      
⚑ Com prova finalMédia 7 ou mais aprova, abaixo de 3 reprova. Entre 3 e 7, passa se (média + final) / 2 for 5 ou mais.

      
◷ VagasA turma tem limite de vagas, o mesmo aluno não entra duas vezes, e turma encerrada não aceita matrícula.

    Como rodar
    
Compilar e executar

    
Você precisa do g++ (MinGW no Windows). Não tem dependência externa: o SQLite vem junto no projeto.

    

      
Clonar o repositóriogit clone https://github.com/Fbelt/Projeto-EDOO-.git
cd Projeto-EDOO-

      
Compilar
A primeira vez demora uns 15 segundos, porque compila o SQLite junto.
make            # Linux / Mac
mingw32-make    # Windows

      
Rodar
Na primeira execução, o banco data/escola.db é criado com dados de exemplo.
./sistema

    


    
Interface web (bônus)

    
A interface em React usa as mesmas classes C++ e o mesmo banco. A pasta web/dist já vem compilada, então não precisa de Node.js para usar. No Windows, o MinGW precisa ter suporte a threads (ex: MSYS2 ou WinLibs).

    

      
Compilar o servidormake servidor            # Linux / Mac
mingw32-make servidor    # Windows

      
Ligar o servidor
Ele fica ouvindo em localhost:8080 e entrega as telas e os dados.
./servidor        # Linux / Mac
.\servidor.exe    # Windows (PowerShell)

      
Abrir no navegador
Para testar, entre como professor Ana Souza ou aluno Joao Silva.
http://localhost:8080

      
Só para quem for mudar as telas
Com o servidor ligado, rode o React em modo de desenvolvimento e abra a URL que o Vite mostrar (normalmente localhost:5173). No fim, npm run build atualiza o web/dist.
cd web
npm install
npm run dev
